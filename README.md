## 5. Scenario-Based Demo & Practice Questions

### Question 1
What is the primary architectural benefit of selecting the OCI VCN-Native Pod Networking CNI plugin when creating an OKE cluster?

A) Pods receive native IP addresses directly from the VCN subnet, enabling direct communication with other VCN resources without overlay NAT overhead
B) Pods cannot communicate with outside internet
C) Kubernetes pods do not consume any IP addresses
D) It eliminates the need for Kubernetes master nodes

- **Correct Answer**: `A) Pods receive native IP addresses directly from the VCN subnet, enabling direct communication with other VCN resources without overlay NAT overhead`  
- **Technical Explanation**: The OCI VCN-Native CNI assigns real VCN private IP addresses directly to each pod, eliminating overlay network translation overhead and enabling native Network Security Group enforcement.

---

### Question 2
Which OKE node type allows developers to deploy Kubernetes pods without managing, provisioning, patching, or scaling any underlying compute instances?

A) Virtual Nodes
B) Bare Metal Worker Nodes
C) Self-Managed Compute Nodes
D) Local SSD Instances

- **Correct Answer**: `A) Virtual Nodes`  
- **Technical Explanation**: OKE Virtual Nodes provide a serverless container execution model where Oracle fully manages the worker node infrastructure, and you pay only for the resources consumed by your pods.
